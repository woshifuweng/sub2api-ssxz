# 客户路径完整验收与修复执行计划

> 状态：执行中。范围包含历史待办、用户补充的客户反馈、GPT-6 Sol/Luna、Claude Opus 5.5、Grok 4.7 实测、PC 端和移动端。

## 0. 现状基线与证据冻结

- [x] 固化正版上游 Sub2API v0.2.8 来源、tag SHA、merge SHA 和自定义父提交。
- [x] 建立官方功能与本地代码/页面/线上证据矩阵。
- [x] 发布预检加入 provenance、config/data 链接和关键页面 HTML 检查。
- [ ] 建立本次客户问题台账，统一记录截图反馈和后续发现。
- [ ] 记录当前工作区测试基线、未验证项和不得自动修改的业务数据。

## 1. 真实模型与模型目录验收（P0）

- [ ] 从运行配置、数据库/渠道、后端模型目录、前端展示四层比对四个目标模型。
- [ ] 检查模型卡片选中状态是否真正写入 Key/会话/请求参数。
- [ ] 使用隔离 QA 账户对四个模型各发起一次最小请求，记录请求模型、有效模型、响应、HTTP 状态、延迟、费用和渠道（脱敏）。
- [ ] 若没有隔离账户/额度/可用渠道，明确列为发布阻塞，不把代码支持当作上线证明。
- [ ] 为未定价、未配置、探针失败和上游超时增加明确状态，不显示虚假的可用价格。

## 2. 客户主流程验收（P0/P1）

- [ ] PC：登录、注册、验证码重试、退出、过期会话、刷新和深链恢复。
- [ ] PC：创建 API Key、复制/撤销、选择模型、文本请求、错误提示和重复点击保护。
- [ ] PC：余额显示与预警阈值、兑换码/订阅/外部商店库存状态。
- [ ] PC：仪表盘、使用记录、渠道状态、渠道定价、文档登录状态。
- [ ] 移动端：同一套核心任务，覆盖窄屏导航、横向溢出、触摸点击和返回/刷新。
- [ ] 图片工作台：打开、上传/选择、生成或失败提示、结果展示、下载/重试。

## 3. 头像与账户资料修复（P1）

- [ ] 盘点并合并重复头像入口/接口，确定一个真实保存路径。
- [ ] 支持鼠标和触摸的选择、裁剪框拖动、缩放、取消、保存、刷新持久化。
- [ ] 处理文件类型、大小、方向、透明图、读取失败和取消上传。
- [ ] 为桌面和移动视口补充组件测试与浏览器操作测试。

## 4. 一致性与体验修复（P1/P2）

- [ ] 文档页与主站共享登录状态和退出状态。
- [ ] 统一余额预警的后端有效配置来源，前端只展示结果。
- [ ] 合并重复或含义相近的仪表盘/使用记录入口，补充页面标题和空/慢/失败状态。
- [ ] 移动端强化登录、模型、账户和图片入口的可发现性。
- [ ] 对慢请求加超时、重试、取消和可读错误；不可用时不永久加载。

## 5. 自动化回归与验收门禁

- [ ] 组件/API 测试覆盖本次修复。
- [ ] Playwright/浏览器矩阵覆盖 PC 与移动关键路径、刷新、深链、失败恢复。
- [ ] 检查控制台错误、未处理 Promise、关键请求耗时和资源加载失败。
- [ ] 运行前端类型检查、构建、单测、发布预检；记录无法在 Windows 上运行的 Linux 专项检查。
- [ ] 只有全部 P0/P1 有证据、四模型真实请求通过或明确阻塞并获批准后，才生成候选发布包。

## 6. 发布与最终汇报

- [ ] 生成候选版本，保留当前线上版本和可回滚指针。
- [ ] 先做候选环境验收，再做正式发布；未获明确授权不修改价格、余额、用户组、渠道启用状态。
- [ ] 正式发布后重新点击关键路径并复核日志/错误率。
- [ ] 汇报完成项、未完成项、阻塞项、实际测试证据、正式网站是否更新和客户复测步骤。

## 当前明确结论

计划包含目前已知的全部待办和用户补充反馈，但不声称能预知未来新问题；新发现必须进入第 0 节台账并走同一验收门禁。四个模型在真实探针和客户确认完成前，状态保持“未验证”。
