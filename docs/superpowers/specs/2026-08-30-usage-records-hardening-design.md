# 使用记录准确性与移动端适配设计

## 目标

在不改变现有桌面端信息结构和视觉风格的前提下，解决使用记录页中容易被忽略的金额、耗时、并发加载、导出一致性和手机端横向滑动问题。

## 已确认问题

1. 正数小额扣费使用两位小数显示，可能被显示成 `$0.00`，与真实扣费含义冲突。
2. 分钟级耗时先拆分钟再四舍五入秒数，边界值可能显示成 `1m 60s`。
3. 连续筛选、翻页或刷新会产生并发请求，较早的响应可能覆盖较新的结果。
4. CSV 导出循环逐页读取响应式筛选条件；导出过程中改动筛选可能混入不同条件的数据。
5. 低于 640px 的手机端仍依赖表格横向滚动。

## 方案比较

### 方案 A：原组件内做小范围加固（采用）

- 金额仅在 `0 < |金额| < 0.01` 时提高可见精度，其他金额保持现有两位显示。
- 耗时先把总毫秒四舍五入成总秒数，再统一换算分钟和秒。
- 加载使用递增请求序号，并在请求开始时快照页码和筛选条件；只有最后一次请求可以更新页面。
- 导出开始时固定筛选和总条数，导出期间禁用筛选与翻页操作。
- 手机端复用同一份表格数据，通过响应式样式将每条主记录变为纵向卡片，详情仍使用现有展开区域。

优点是改动集中、没有重复数据逻辑、可回滚；缺点是移动端 CSS 规则比单纯横向滚动稍多。

### 方案 B：新增独立手机列表组件

桌面表格和手机卡片各维护一套模板。视觉自由度高，但会复制字段、展开和测试逻辑，后续容易出现两端数据不一致，因此不采用。

### 方案 C：继续横向滚动并增加提示

风险最低，但没有解决手机端必须右滑的问题，不满足本轮目标，因此不采用。

## 详细设计

### 金额

- 金额为零时继续显示 `$0.00`。
- 绝对值大于等于 `$0.01` 时继续显示两位小数。
- 非零且绝对值小于 `$0.01` 时显示 4 至 8 位小数，直到能看见真实非零值。
- 悬浮提示继续保留精确金额，详情和 CSV 保留原始数值。

### 耗时

- 小于一分钟的规则保持不变。
- 一分钟及以上先计算 `roundedTotalSeconds = Math.round(ms / 1000)`，再按 60 进位，永不出现 `60s`。

### 请求一致性

- 每次 `loadUsageOverview` 分配递增序号并快照页码、API Key、模型和日期。
- 响应回来后若序号不是最新值，则直接丢弃，不能更新列表、统计、错误状态或 loading 状态。
- 最新请求无论成功或失败都负责结束 loading。

### 导出一致性

- 点击导出时冻结筛选条件和预期总条数。
- 每一页请求都使用同一快照，不能读取导出过程中变化的响应式筛选值。
- 导出期间禁用 API Key、模型、日期、重置、刷新和翻页入口。
- 下载链接挂载后触发下载，并在下一个事件循环释放对象地址，兼顾浏览器兼容性和内存清理。

### 手机端布局

- 断点设为 640px。
- 隐藏表头，将主记录行显示为带边框的纵向卡片。
- 时间和模型占整行；用量、耗时、扣费以标签和值成对显示；展开按钮固定在卡片右上角。
- 详情行继续在当前记录下方显示，不创建第二套组件或数据流。
- 表格容器和页面本身均不得出现横向溢出。

## 测试与验收

- 单元测试覆盖小额非零金额、零金额、`119999ms` 进位、旧请求不能覆盖新请求、导出筛选快照和导出期间禁用状态。
- 保留现有展开、复制、分页和数字列对齐测试。
- 运行相关测试、完整前端测试、类型检查、Lint、生产构建和 `git diff --check`。
- 使用真实组件分别在桌面宽度和 390px 手机宽度检查默认、展开、筛选、导出状态；确认无横向滚动、无错位、无控制台错误。

## 范围边界

- 只改用户端使用记录页及其测试、必要的中英文说明。
- 不改后台、接口协议、数据库、计费规则和生产数据。
- 本轮不部署正式环境，除非用户另行明确授权。
