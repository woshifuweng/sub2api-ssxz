# 使用记录表头与数据对齐设计

## 目标

让用户端 `/app/usage` 的“用量、耗时、扣费”表头与每行对应数据严格共用同一条右侧对齐线，消除表头看似属于后一列的错位感。

## 问题原因

表头和数据都带有 `num-cell` 类，但基础单元格规则 `.usage-table td` 的选择器优先级高于 `.num-cell`。因此表头实际右对齐，数据仍然左对齐；列本身没有错位，是同一列中的文字落点不一致。

## 实施范围

- 只修改 `frontend/src/views/user/AppUsageView.vue` 的数字列对齐规则。
- 在 `AppUsageView.spec.ts` 增加数字表头与数据采用同一对齐方式的回归断言。
- 保留现有列宽、筛选、分页、展开详情、复制定位码、接口及计费逻辑。
- 不修改管理员页面、其他客户端页面、后端、数据库或生产配置。

## 方案

使用更明确的同级选择器同时约束数字表头和数字数据单元格：

```css
.usage-table th.num-cell,
.usage-table td.num-cell {
  text-align: right;
}
```

该方案直接修复优先级冲突，不引入固定像素列宽，也不改变表格语义和响应式行为。时间、模型继续左对齐；用量、耗时、扣费统一右对齐；详情按钮保持原位置。

## 验收标准

- “用量、耗时、扣费”三个表头分别与下面对应数据的右边缘一致。
- 普通 Token、慢请求、图片用量和零扣费记录均不破坏对齐。
- 展开详情前后主表列宽和文字落点不跳动。
- 组件回归测试、类型检查、前端测试和生产构建通过。
- 在与用户截图相同的桌面状态下重新截图，人工确认对齐。
