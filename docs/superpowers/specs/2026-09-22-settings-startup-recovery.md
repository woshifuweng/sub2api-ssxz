# 设置页与首屏加载恢复规格

## 目标

解决打开网站停在原始 Loading 页面、系统设置页启动时出现 404、设置项显示默认值误导管理员，以及暗色界面下开关/按钮难以识别的问题，同时保留现有 SSXZ UI 风格和全部业务配置。

## 已确认的根因

1. `frontend/index.html` 的首屏兜底是在 `659ea5e23` 中新增的。它能保护空白页，但样式是原始内联样式；当入口脚本没有执行或启动阶段失败时，用户会一直看到它。
2. 前端 TLS 指纹设置请求使用 `/admin/settings/tls-fingerprint`，后端实际注册的是 `/admin/tls-fingerprint-profiles`。这是确定的接口契约错误。
3. `SettingsView.vue` 在挂载时并行启动多个设置请求。部分请求失败后只写控制台，主设置请求即使失败也会在 `finally` 中结束 Loading，页面可能把默认值误认为真实配置。
4. 共用 Toggle 没有可见状态文字、明确的无障碍名称和足够清晰的关闭态对比度。设置页的窄宽度容器和标签栏还会造成横向挤压。

## 产品行为

- 首屏失败时显示品牌化的错误状态、失败阶段、手动重试按钮和“保留当前页面内容”的说明；不自动循环刷新，不把原始异常堆栈展示给用户。
- 设置页分区加载。必需的站点设置失败时阻止保存并提供重试；可选配置失败时保留分区并显示“暂时不可用”，不能自动写入空默认值。
- TLS 指纹功能统一使用后端已经存在的 `/admin/tls-fingerprint-profiles` 契约，并补充前端测试，防止再次出现路径漂移。
- Toast 在窄屏下不遮挡主要内容；错误提示包含上下文和重试入口，不直接把 Axios 原始英文错误作为唯一内容。
- Toggle 维持现有蓝色主色，但扩大可点击区域、提高关闭态可见度、提供 `aria-label`/`aria-describedby` 和可选的开/关文字。
- 设置页在桌面使用更宽的内容区，在小屏将标题、说明、控件堆叠，标签栏可横向滚动但不裁剪正文。

## 不在本次范围

- 不修改客户余额、模型价格、分组、API Key、账号、Redis、数据库或服务器运行配置。
- 不替换整个上游 UI，不重做全站所有页面；只改公共错误/开关/提示基础样式以及系统设置页布局。
- 不引入自动清缓存或无限自动刷新，避免丢失未提交的表单。

## 验收标准

- 入口脚本、语言包、路由懒加载失败时，页面不再停留在原始黑底 Loading；用户能看到可读的失败提示和一次明确的手动重试。
- 设置页首次进入不再产生 TLS 指纹 404；TLS 配置的读取、开关保存、配置新增/编辑/删除均使用正确路径。
- 任一可选设置请求失败时，不出现“暂无配置”冒充真实空配置；必需设置未成功加载时保存按钮不可用。
- 开关在暗色和窄屏下清晰可见，键盘焦点和屏幕阅读器都有明确反馈。
- 前端类型检查、设置页测试、首屏恢复测试和生产构建通过；不影响既有业务测试。
